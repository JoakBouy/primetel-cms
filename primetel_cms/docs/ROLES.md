# Role privileges — Primetel CMS

There are 8 roles, defined in `apps/accounts/models.py`. Login itself is
open to any authenticated user; the roles below grant access to specific
actions. **`ADMIN` and Django superusers can do everything.**

This document is generated by reading every `@requires_role` decorator in
the codebase plus the `EncounterManager.for_user()` rule. If you change a
decorator, update this file too.

## Roles at a glance

| Code           | Display name | Typical user                                    |
| -------------- | ------------ | ----------------------------------------------- |
| `RECEPTIONIST` | Receptionist | Front desk, registration, billing               |
| `NURSE`        | Nurse        | Triage, vitals, basic patient management        |
| `CLINICIAN`    | Clinician    | Doctors, COs — write SOAP notes, prescribe      |
| `COUNSELLOR`   | Counsellor   | Mental-health practitioners                     |
| `PHARMACY`     | Pharmacy     | Pharmacy staff — dispense, stock                |
| `LAB`          | Lab          | Laboratory technicians                          |
| `FINANCE`      | Finance      | Billing, invoicing, payments                    |
| `ADMIN`        | Admin        | Clinic administrator — bypasses all role checks |

## Mental-health encounter PHI rule

Stricter than the role decorators above. Defined in
`apps/encounters/models.py` (`EncounterManager.for_user`). For any encounter
where `encounter_type == "MENTAL_HEALTH"`:

| Role           | Visibility                                                        |
| -------------- | ----------------------------------------------------------------- |
| ADMIN          | Sees all MH encounters                                            |
| COUNSELLOR     | Sees all MH encounters                                            |
| CLINICIAN      | Sees only MH encounters where they are the assigned clinician     |
| Anyone else    | 404 — the encounter is invisible (existence not leaked by ID)     |

Unauthorised access returns **404, not 403**, so MH encounter IDs cannot be
enumerated.


## Edge cases worth knowing

- **Patient list and chart** are protected by `@login_required` only, not
  by `@requires_role`. Any authenticated user can browse them. Writes
  (register/edit/flag/photo) are role-gated.
- **Encounter detail (read)** is `@login_required`, but the queryset is
  pre-filtered by `Encounter.objects.for_user(user)`, so the MH rule
  applies even when reading.
- **Users with no role** can log in but cannot do anything role-gated.
  They can still read patient lists and encounter detail. **Always assign
  a role to a production user.**
- **NURSE** has a deliberately tight footprint: triage and vitals only.
  They cannot start encounters, prescribe, or order labs.
- **CLINICIAN** is the only role that can place lab orders or write
  prescriptions.
- **PHARMACY** cannot read clinical encounter detail unless it appears in
  their Rx queue.

## Assigning a role to a user

1. Log in as ADMIN at `/admin/`.
2. Navigate to **Accounts → Users**.
3. Open the user, set the **Role** field (drop-down), save.
4. The user must log out and back in for the role to take effect on
   already-cached requests; new requests pick up the role immediately.

Roles themselves are seeded once by `python manage.py seed_data` (runs
automatically on every Render build). Don't edit role codes — the
decorators reference them by string.
